# telescope-examples-graphql

A real [graphql-java](https://www.graphql-java.com/) server, served over the JDK's built-in
`com.sun.net.httpserver.HttpServer`, that turns a GraphQL `createUser(input: {...})` argument `Map<String, Object>` into
a typed `User` record. It exists to answer one question: **how do you do Map→POJO in a GraalVM native image without a
pile of reflection config?**

## The two entry points

Both run the same `GraphQlServer` harness (schema, JDK `HttpServer`, self-test mutation); they differ only in the
`Map -> User` converter the resolver uses:

| Entry point              | Converter                                   | Run                                                     |
| ------------------------ | ------------------------------------------- | ------------------------------------------------------- |
| `RuntimeFromMapServer`   | runtime `Telescope.fromMap(...)` (JVM only) | `./gradlew :examples:graphql:runRuntimeFromMapServer`   |
| `GeneratedFromMapServer` | generated `UserFromMap` (native-clean)      | `./gradlew :examples:graphql:runGeneratedFromMapServer` |

`GeneratedFromMapServer` uses `UserFromMap` / `AddressFromMap`, generated by the `@FromMap` annotation processor from
`@FromMap` on `User` / `Address`: a direct `new User(...)` with inline String/int/enum coercion and nested recursion, no
`SerializedLambda`, no `LambdaMetafactory`, no reflection. It is the entry point the native image builds.

## Why the runtime path can't go native

Runtime `Telescope.fromMap(...)` recovers each field name from its `User::name` method reference via `SerializedLambda`
(reflectively invoking the lambda's `writeReplace`). GraalVM does not synthesise `writeReplace` on non-serializable
lambdas, so that path **builds but dies at runtime** in a native image:

```
java.lang.IllegalArgumentException: Expected a method reference to a record component / bean property accessor
    at io.github.eschizoid.telescope.internal.LambdaIntrospection.resolveMethodName
    at io.github.eschizoid.telescope.Telescope.fromMap
Caused by: java.lang.NoSuchMethodException: ...$$Lambda/0x...writeReplace()
```

The generated (reflection-free) converter has none of that machinery, so it just works.

| Map→POJO path                                        | Native build | Native runtime                            | Reflection registered |
| ---------------------------------------------------- | ------------ | ----------------------------------------- | --------------------- |
| Generated shape (`UserFromMap`, = `@FromMap` output) | builds       | **works**                                 | ~0                    |
| Runtime `Telescope.fromMap` (`SerializedLambda`)     | builds       | **`NoSuchMethodException: writeReplace`** | 1,097 types           |

That is the case for the compile-time `@FromMap` tier: the runtime tier is fine on the JVM and wrong in native image;
the generated tier is native-clean by construction.

## Native build

Requires a GraalVM with `native-image` (Oracle GraalVM, GraalVM CE, Liberica NIK, …). Point `GRAALVM_HOME`/`JAVA_HOME`
at it — the plugin otherwise picks the project's plain-JDK compile toolchain, which has no `native-image`:

```bash
GRAALVM_HOME=/path/to/graalvm-21 JAVA_HOME=/path/to/graalvm-21 \
  ./gradlew :examples:graphql:nativeCompile
./examples/graphql/build/native/nativeCompile/graphql
```

The binary starts the GraphQL server, runs one mutation against itself, and prints the response — built `--no-fallback`
with no hand-written reachability config (graphql-java ships its own native metadata; the converter needs none).

## Layout & tests

```
src/main/java/.../examples/graphql/
  model/    User, Address, Role        — the @FromMap domain records
  server/   GraphQlServer              — reusable graphql-java + HttpServer harness (serveOnce)
            RuntimeFromMapServer       — runtime-tier entry point
            GeneratedFromMapServer     — generated-tier entry point (the native-image main)
src/test/java/.../examples/graphql/server/
  GraphQlServerTest                    — asserts both tiers through the server
```

The entry points just run and print; verification lives in the test:

```bash
./gradlew :examples:graphql:test
```
